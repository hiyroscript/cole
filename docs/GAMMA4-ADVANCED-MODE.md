# Optional Gamma generation: investigation and decision

Gamma Core remains the default deterministic engine. No Gamma request selects Madon, downloads a generation model, or enables an unverified mode. This release implements the useful local alternative: retrieval with evidence acceptance, typed task execution, forward deduction over supplied rules, extractive document analysis, and optional MiniLM retrieval.

The real production browser probe on 2026-10-26 exposed `navigator.gpu` but returned no adapter. Chromium 156 reported `adapter=false`, `shaderF16=false`, `generated=false`. See [the probe](gamma4/final-runtime/generation-probe.log). It exited with the script's unsupported-hardware status, not a passing generation result.

Publisher metadata was fetched from Hugging Face for three candidates; exact revisions and licenses are retained in [model-metadata.json](gamma4/final-runtime/model-metadata.json). The `safetensors` value is the Hub API's tensor parameter count, not download bytes or runtime RAM.

A future Gamma generation setup needs its own explicit identity, pinned packaged runtime/artifacts, download estimate and consent, actual progress, cancellation, recovery, bounded input/output, independently removable cache and Core fallback. It must not inherit Madon's readiness implicitly. Source text remains evidence data with IDs; generated output has no tool authority. Model proposals still require deterministic validation and explicit authorization for side effects.

The MV3 extension cannot download remote executable model code under its current policy. It ships neither semantic inference nor generation assets. A future extension runtime must package executable code, retain current permissions and validate offline behavior separately. Web success would not establish extension compatibility.

Open gates: actual generation on supported GPU hardware, a packaged CPU-generation experiment, grounded answer quality and French evaluation on untouched cases, peak process/device memory, download/initialization/latency measurements, cancellation during real generation, cache eviction/recovery, offline generation, and physical-device/browser testing. Neither the hardware probe nor publisher metadata substitutes for those measurements.
